## Design spike and dependency decision

Selected `webview2-com = 0.38.2` (exact pin, MIT, declared Rust 1.74), with
`windows = 0.61` (resolved 0.61.3, MIT OR Apache-2.0). The sys bindings and callback
macros are MIT. Cargo metadata and local crate sources establish these versions,
licences, supported GNU target, asynchronous completion interfaces, and loader
linkage. The actual Windows GNU all-target check and clippy validate the API use.
See the [binding documentation](https://docs.rs/crate/webview2-com/0.38.2).

Also inspected `wry 0.53.5` (MIT OR Apache-2.0, declared Rust 1.77). Its Windows
backend uses the same `webview2-com 0.38` and `windows 0.61`, and additionally
introduces its raw-window-handle, HTTP, DPI, and cross-platform abstractions.
Direct bindings provide the required accelerator, focus, policy, controller,
background, completion, and token-removal control without another windowing
abstraction. No additional windowing toolkit was added. New dependencies are
under `target.'cfg(windows)'.dependencies`.

## Lifecycle, threading, failure handling

`init()` remains empty. Constructing a host creates GTK state and queues commands;
engine creation starts only after the DrawingArea realizes. It calls
`gdk_window_ensure_native` through gdk-rs and the explicitly declared
`gdk_win32_window_get_handle` import, linked from GDK3. All COM objects and calls
stay on the GTK thread. A thread-local, balanced STA initialization coexists with
GTK's Win32 message pumping; creation uses completed handlers and never waits
synchronously for the runtime.

The environment uses `%LOCALAPPDATA%/impro/WebView2`. Missing, empty, relative,
drive-relative, or NUL-containing profile paths produce a notice, without falling
back to the executable directory. `GetAvailableCoreWebView2BrowserVersionString`
detects runtime availability. Environment/controller/setup/load errors, and a
60-second creation/ready timeout, show a centered dim notice with the error and
an actionable [Microsoft download link](https://developer.microsoft.com/microsoft-edge/webview2/).
`IMPRO_GIT_PAGES=notice` forces this path before runtime detection.

Map/unmap shows/hides the controller and uses the existing page pause/resume
protocol. Hidden graph refreshes defer Git collection. Focus refresh remains
300 ms debounced; WebView2 GotFocus also schedules it. Unrealize closes the
controller and prepares the same state replay used for reloads. A process-failed
event reports its reason, then recreates the environment/controller from a GLib
idle callback and replays appearance/settings/data/selection.

COM callbacks own only weak state. Controller epochs invalidate late callbacks
and script results; shared Git generations still reject stale worker results.
Reentrant calls clone state/callbacks out before invoking COM or GTK. Teardown
removes every successfully registered COM event token before `Close`, cancels
timers, closes the native surface, and is idempotent. Failure teardown and keyboard
forwarding run from idle callbacks rather than inside synchronous engine events.

## Message protocol parity

The injected document-created shim supplies
`window.webkit.messageHandlers.impro.postMessage(m)` and passes the original
object to `window.chrome.webview.postMessage(m)`. WebView2 receives it with
`WebMessageAsJson`, matching WebKit's JavaScriptCore `to_json(0)` object encoding.
There is no extra stringify/string-unwrapping layer. Both engines use the same
parser and `Inner::message` dispatcher, including rejection of non-object payloads.

| Linux handler or JS operation | Windows equivalent |
|---|---|
| `load_html(assets::{graph,commit}_html(), about:blank)` | `NavigateToString` with the exact same embedded document; no relative files or virtual host needed |
| UserContentManager `impro` handler | document-created shim + `WebMessageReceived` + `WebMessageAsJson` |
| `ready` | same ordered queue drain, pause/resume first, then queued settings/data; commit worker starts after handshake |
| `painted`, generation | same generation filter and `PaintTimings` calculation |
| `open-commit`, hash | same callback dispatch |
| `open-file`, path, line | same worker canonicalization, repository containment, existence, one-based line clamping |
| `refresh`, `orientation` | same graph refresh/settings/callback behavior |
| `copy` | same GTK clipboard operation |
| `expand`, path/start/end | same bounded context queue/worker and `provideContext` response |
| `error`, message | same `connect_error`; shim also reports uncaught exceptions and rejected promises |
| `evaluate_javascript` | asynchronous `ExecuteScript`; failed completion reaches `connect_error`, stale epochs/generations are discarded |
| theme, motion, orientation, options, font size, selection, HEAD focus | identical shared JS command generation and data |
| navigation/new-window/context-menu policy | initial `about:blank` navigation only; reject frames/new windows; disable default menus |
| load-failed / process termination | notice for initial load failure; report process failure and asynchronously recreate |

## Engine policy mapping

| Requirement | Implementation |
|---|---|
| developer extras off | `AreDevToolsEnabled=false`; only `IMPRO_GIT_DEVTOOLS=1` enables them |
| no console to stdout | no console forwarding or console event subscription |
| no browser shortcuts/menus/status/zoom/error page | corresponding Settings properties false; pinch zoom false too |
| no password saving/autofill/swipe | Settings4/Settings6 properties false |
| no new windows/navigation/permissions | handled new-window request, navigation cancellation, frame cancellation, permission DENY |
| no page cache | Chromium BackForwardCache feature disabled; navigation outside the initial document is denied |
| no HTML database/local storage | document-created shim disables local/session storage, indexedDB, and openDatabase |
| no DNS prefetch / external resources | DNS prefetch/background flags; all external resource requests receive HTTP 403 |
| no WebGL/WebAudio/media | WebGL disabled; AudioContext/RTCPeerConnection unavailable through shim; web audio muted; media/network permissions denied and downloads canceled |
| no host-object or script-dialog UI | host objects and default script dialogs disabled |

Chromium has no one-to-one WebKit `enable_media` switch. The page policy uses the
restrictions above; neither page uses media. Browser background internals are
outside the embedded page request filter.

## Keyboard and focus

The native surface participates in GTK focus traversal. GTK focus enters WebView2
with `MoveFocus`; GotFocus synchronizes GTK's focused widget without recursively
moving native focus. MoveFocusRequested leaves the page through GTK TabForward or
TabBackward traversal, scheduled outside the COM event.

AcceleratorKeyPressed marks recognized keys handled immediately, then posts a
GDK key-press event to the GTK toplevel through GLib. This runs the existing window
handler, accelerators, and editor ancestor handlers without changing the host crate.
Forwarded mappings:

- Ctrl+W, Ctrl+Tab, Ctrl+Shift+Tab, Ctrl+PageUp/PageDown.
- Ctrl+P/O, Ctrl+Shift+P, Ctrl+S/Shift+S, Ctrl+Q, Ctrl+B.
- Ctrl+Shift+F/M/5/F11; Ctrl+Alt+H/T/G; Ctrl+Shift+Alt+G.
- Ctrl+grave, Ctrl+Alt+grave, Ctrl+comma, Ctrl+slash, Ctrl+equal/minus/0.
- Escape and F1. If GTK does not consume Escape, dispatch it back to the active
  page element so the graph can dismiss its tooltip/keyboard selection.

Arrows, unmodified PageUp/PageDown, Enter, Space, slash, text entry, clipboard
shortcuts, and bare Tab remain with the page. Bare F11 is not an application
binding in the inspected command definitions and browser fullscreen shortcuts are
disabled. Native focus, physical keyboard layouts/OEM virtual keys, Tab traversal,
and shortcut delivery need Windows runtime confirmation; see the runner checklist.

## DPI and background

DrawingArea allocation is in GTK logical pixels. Controller bounds are
`(0, 0, width * scale_factor, height * scale_factor)` with saturation and nonnegative
sizes. BoundsMode is explicitly USE_RAW_PIXELS so rasterization does not multiply
those bounds again. ShouldDetectMonitorScaleChanges is enabled; WebView2 follows
the monitor scale for CSS pixels. Allocation and GTK scale notifications update
bounds and notify the controller that its parent position changed.
See [Microsoft's controller scaling contract](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2controller3?view=webview2-1.0.3537.50).
The runner asserts `innerWidth * devicePixelRatio` matches the physical GTK child
width within two pixels and logs both values. Fractional/mixed-monitor scaling
still needs visual verification.

The shared palette updates `DefaultBackgroundColor` before navigation/first paint;
the DrawingArea paints the same stored color while asynchronous creation is pending.
Theme updates use the existing shared page calls after that.

## WebView2Loader.dll packaging

GNU uses dynamic loader linkage, unlike MSVC's static loader. This is established
by `webview2-com-sys 0.38.2/src/lib.rs` and its build script, not inferred from the
MSVC behavior. The build script copies all SDK loader files into OUT_DIR.

Ship this exact x64 file beside `impro.exe` through `packaging/windows/bundle.py --extra`:

```text
<CARGO_HOME>/registry/src/<registry>/webview2-com-sys-0.38.2/x64/WebView2Loader.dll
```

The identical build output is:

```text
<CARGO_TARGET_DIR>/x86_64-pc-windows-gnu/<profile>/build/webview2-com-sys-<hash>/out/x64/WebView2Loader.dll
```

Verified PE32+ x86-64 DLL, SHA-256:
`8427b1fc58ec707813e5c0a51eb5d69397bb333250a7b891be4d3b123f1e0f1c`.
The import library and `WebView2LoaderStatic.lib` are not runtime bundle files.
A missing Evergreen installation is handled by the notice; a missing loader DLL
must be prevented by packaging because Windows resolves imported DLLs before
application startup. Packaging files are outside this task's ownership.

## Windows runner priorities / open issues

Run `cargo test -p impro-gitviews --test windows_webview -- --nocapture` with the
x64 loader beside the executable/in PATH, GTK3 available, and Evergreen installed.

1. **Link/startup and ready:** verify the explicit GDK3 import resolves and both
   asynchronous environment/controller creation and the document-created shim
   complete. A notice is a test failure in the real-engine portion.
2. **Paint/data/bridge:** look for two repository rows painted, fixture rendering,
   queued vertical orientation, graph open-commit, commit subject, and resolved
   open-file roundtrip messages. A failure here distinguishes loading/bridge from
   Git-data issues.
3. **Lifecycle:** look for pause/resume, a deferred hidden refresh, closing during
   creation without affecting a sibling, repeated shutdown, blocked navigation,
   and forced-notice completion. Check logs for GTK criticals and COM failures.
4. **Focus/keyboard:** manually exercise Tab/Shift+Tab across adjacent GTK entries,
   graph/commit page controls, Ctrl+W/Tab/Shift+Tab/P/Shift+P/Alt+H/B, Escape, and
   Ctrl+Shift+F11. The test does not synthesize physical keyboard input.
5. **DPI/theme:** inspect the logged native-width equation, then resize and move
   between 100%, fractional, and 200% monitors. Check borders, font scale, mouse
   hit testing, and the absence of a light flash when opening a dark page.
6. **Recovery/runtime absence:** manually terminate a browser/renderer process,
   verify error delivery and recreation/state replay, then test a machine without
   Evergreen. Forced notice is automated; actual absent-runtime and process-crash
   conditions are not exercised here.
